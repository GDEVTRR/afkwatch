# Bot Remote

Run up to **5 Minecraft bots** ([Mineflayer](https://github.com/PrismarineJS/mineflayer)) on your **Windows PC** and control them from your **iPhone** through a small **cloud relay** on Render.

```
 iPhone (SwiftUI) ──HTTPS/WSS──►  Cloud relay (Node + Socket.IO + Postgres)  ◄──WSS──  Windows PC (Electron + Mineflayer)
   scan QR, commands, logs          auth · pairing · routing only                      bots run HERE, never in the cloud
```

* The cloud **never runs bots** and has no dashboard, no screenshots, no background jobs.
* The PC only makes an **outbound** connection (no port forwarding).
* The phone can only send a fixed whitelist of bot-management commands. There is **no remote shell**.

## Repository layout

```
BotRemote/
  cloud/      Express + Socket.IO relay, Postgres store, render.yaml, .env.example, tests
  desktop/    Electron app (tray) + agent (Socket.IO client) + Mineflayer bot manager + UI
  ios/        SwiftUI app sources + XcodeGen project.yml
  scripts/    check-protocol.js (verifies cloud/desktop protocol files are identical)
```

## 1. Deploy the cloud server on Render

1. Push this repository to GitHub/GitLab.
2. Render dashboard → **New → Blueprint** → select the repo. Render reads `cloud/render.yaml` (use *"Blueprint file path" = `cloud/render.yaml`* if asked; `rootDir: cloud` is set inside).
3. It creates a **web service** (`starter`) and a **Postgres database** (`basic-256mb`) and wires `DATABASE_URL` automatically. `TOKEN_PEPPER` is generated for you.
4. (Recommended) In the service's *Environment* tab set `REGISTRATION_KEY` to a long random string so strangers cannot register desktops on your server. Enter the same key once in the desktop app.
5. Wait for the deploy, then open `https://<your-service>.onrender.com/healthz` → `{"ok":true}`.

> **Why not Render's free tiers?** Free web services spin down when idle (your PC would be disconnected) and free Postgres databases expire after 30 days (pairings would be lost). If you want a free database, create one at Neon/Supabase, set `DATABASE_URL` yourself and `DATABASE_SSL=true`, and delete the `databases:` block + `fromDatabase` entry from `render.yaml`.

### Environment variables

| Variable | Required | Description |
|---|---|---|
| `NODE_ENV` | prod | `production` enables HTTPS enforcement and strict config checks. |
| `PORT` | no | Provided by Render. Default `3000`. |
| `DATABASE_URL` | **prod** | Postgres connection string. Pairing data lives here, not on Render's ephemeral disk. |
| `DATABASE_SSL` | no | `true` if the DB requires TLS (external URLs, Neon, Supabase). Not needed for Render's internal URL. |
| `TOKEN_PEPPER` | **prod** | ≥32 chars. HMAC key for token hashes. Never hardcoded; generated by `render.yaml`. Changing it invalidates all pairings. |
| `REGISTRATION_KEY` | no | If set, desktops must present it to register. |
| `TRUST_PROXY` | no | Reverse-proxy hops (Render = `1`, default in production). |
| `ALLOW_MEMORY_STORE` | dev | `true` permits the non-persistent in-memory store (development/tests only). |

The server refuses to start in production without `DATABASE_URL` and a strong `TOKEN_PEPPER`.

Local run: `cd cloud && npm install && cp .env.example .env` (export the vars, or just `ALLOW_MEMORY_STORE=true node server.js`).

## 2. Windows desktop app

**Requirements:** Windows 10/11, [Node.js 18+ LTS](https://nodejs.org) (only needed to build/run from source).

```bat
cd desktop
npm install
npm start            :: run in development
npm run dist         :: build installer -> desktop\dist\Bot Remote Setup 1.0.0.exe
```

First run: **Cloud & pairing** → enter your Render URL (`https://….onrender.com`) → *Save & connect* (enter the registration key if you set one). The PC registers itself once; its secret is stored encrypted with Windows DPAPI (Electron `safeStorage`).

Features: add/edit/delete up to 20 bot profiles, **max 5 running at once**, per-bot console + chat, uptime, auto-reconnect with configurable delay, offline or Microsoft auth, version auto-detect, tray icon (closing the window keeps bots running; *Quit* in the tray stops everything), optional start with Windows.

**Microsoft accounts:** start the bot and watch its console: it prints a `microsoft.com/link` URL and a code. Sign in once; the token is cached in `%APPDATA%\Bot Remote\auth-cache`.

Chat messages starting with `/` are sent to the Minecraft server as in-game commands. That is Minecraft behaviour and is limited to the bot's own in-game permissions; there is no way to run anything on your PC.

## 3. iOS app

**Requirements:** a Mac with Xcode 15+, iOS 16+ device (the simulator has no camera: use *Enter pairing text*).

**Option A: XcodeGen (recommended)**
```bash
brew install xcodegen
cd ios && xcodegen generate && open BotRemote.xcodeproj
```
**Option B: manually**
1. Xcode → *File → New → Project → iOS App* (SwiftUI, name `BotRemote`, min iOS 16).
2. Delete the generated `ContentView.swift`/`BotRemoteApp.swift`; drag in the folders `ios/BotRemote/App`, `Models`, `Services`, `Views` (*Copy items*, *Create groups*).
3. *File → Add Package Dependencies…* → `https://github.com/socketio/socket.io-client-swift` (≥ 16.1.1) → add product **SocketIO**.
4. Target → *Info*: add `Privacy - Camera Usage Description` and set *Supported orientations* to Portrait if desired.

Select your Team under *Signing & Capabilities*, choose your iPhone and **Run**.

### Screens
Dashboard (PC status, `n / 5` active, bot cards, pull-to-refresh, start/stop all) → Bot details (status, username, server, uptime, start/stop) → Console (live log, send chat, clear) → Settings (server URL, pairing, disconnect).

## 4. QR pairing

1. Desktop → *Cloud & pairing* → **Generate QR code** (needs a cloud connection).
2. iPhone → *Settings → Scan pairing QR code* → confirm the server shown → **Pair**.
   (No camera? Copy the *Pairing text* shown under the QR into *Enter pairing text*.)
3. The code is **single-use** and **expires after 5 minutes**. Generating a new code invalidates the previous one.

Revoke devices from the desktop (*Paired devices → Revoke*) or from the phone (*Disconnect this device*).

## 5. Security model

* **QR payload** = `{v, u: serverURL, c: one-time code}`. Contains no secrets that outlive the pairing: the code is stored only as an HMAC hash, consumed atomically (`DELETE … RETURNING`), expires in 5 minutes.
* **Desktop credential** (`deviceId` + 256-bit token) is created at registration, shown once, stored hashed on the server and DPAPI-encrypted on the PC. **It is never sent to the phone.**
* **Phone credential**: 256-bit token returned once by `POST /api/pair/complete`, stored in the iOS Keychain, hashed on the server. A phone is bound to exactly one desktop.
* Every Socket.IO connection is authenticated in the handshake; every event payload is validated and sanitized on the cloud **and again** on the desktop. Unknown actions are rejected.
* Per-socket token-bucket rate limits, HTTP rate limits, 4 KB JSON body limit, 256 KB socket message limit, `helmet`, HTTPS enforced in production.
* No secret is hardcoded; the server won't boot in production without them.
* Rotating `TOKEN_PEPPER` or wiping the DB invalidates every credential (re-register + re-pair).

## 6. Protocol (cloud ⇄ desktop ⇄ iOS)

Single source of truth: `cloud/services/protocol.js` (byte-identical copy in `desktop/agent/protocol.js`; `npm run check:protocol` enforces this). iOS names live in `ios/BotRemote/Models/Models.swift`.

| Direction | Event | Payload |
|---|---|---|
| desktop→cloud (ack) | `desktop:pairing:create` | → `{code, expiresAt}` |
| desktop→cloud (ack) | `desktop:phones:list` / `desktop:phones:revoke {phoneId}` | |
| desktop→cloud→phones | `bots:snapshot` | `{bots[], activeCount, maxActive}` |
| desktop→cloud→phones | `bot:status` | `{bot}` |
| desktop→cloud→phones | `bot:log` / `bot:chat` | `{botId, entry:{t,k,m}}` |
| phone→cloud→desktop (ack) | `command` | `{action, botId?, message?, limit?}`; actions: `bot.start bot.stop bots.startAll bots.stopAll bot.chat bot.logs snapshot` |
| cloud→* | `presence` `{desktopOnline}` / `{phonesOnline}`, `pairing:completed`, `phones:changed`, `revoked`, `replaced` | |

Acks are `{ok:true,data}` or `{ok:false,error:{code,message}}` (codes: `BAD_REQUEST`, `UNSUPPORTED_ACTION`, `DESKTOP_OFFLINE`, `TIMEOUT`, `LIMIT_REACHED`, `DUPLICATE_ACCOUNT`, `NOT_FOUND`, `NOT_ONLINE`, `BOT_RUNNING`, `RATE_LIMITED`, …).

HTTP: `POST /api/desktop/register`, `POST /api/pair/complete`, `POST /api/phone/unpair`, `GET /healthz`.

**Heartbeat / monitoring:** Socket.IO's built-in ping/pong (25 s interval, 30 s timeout) detects dead links on all three sides; presence events tell each side whether the other is online. There are no additional app-level timers.

## 7. Resource usage (what to realistically expect)

Nothing runs for free, but the design avoids waste:

* Event-driven everywhere, **no polling**. Uptime is computed client-side (the only 1 s timers are in the UI while an online bot is on screen).
* Closing the window **destroys the renderer process**; only the main process (agent + bots) stays resident. Hardware acceleration is disabled and the V8 heap of renderers is capped.
* Bot console logs are ring buffers (500 lines × ≤400 chars per bot); messages are length-capped; log/chat events are **forwarded to the cloud only while a phone is connected** and are rate-limited.
* One WebSocket-only Socket.IO connection (no long-polling); one reconnect timer per bot; instances are torn down with a generation counter so stale callbacks are ignored.
* Expect an idle Electron tray app to use on the order of 100–150 MB RAM plus roughly 20–60 MB per connected Mineflayer bot (chunk data dominates and grows with server view distance), and low single-digit CPU % when bots are idle. Measure on your own PC; these are rough guides, not guarantees.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| Desktop: *"Cannot reach server"* | Check the URL (must be `https://…`), open `/healthz` in a browser. Free Render plans may be asleep. |
| Desktop: *"This PC is no longer registered"* | The DB was reset or `TOKEN_PEPPER` changed: **Reset registration**, connect again, re-pair phones. |
| *"Invalid registration key"* | Enter the `REGISTRATION_KEY` configured on Render in the key field once. |
| iPhone: *"pairing code is invalid or expired"* | Codes last 5 minutes and work once. Generate a new QR. |
| iPhone: *"Your PC is offline"* | Desktop app/tray isn't running or isn't connected (check the tray tooltip and Cloud status). |
| Bot: `LIMIT_REACHED` | Only 5 bots may be active (connecting/online/reconnecting all count). Stop one first. |
| Bot: `DUPLICATE_ACCOUNT` | Two bots use the same username on the same server; the server would kick one. |
| Bot kicked with *"Connection throttled"* | Raise the reconnect delay (servers throttle rapid re-logins). |
| Bot can't join: version mismatch | Set the *Minecraft version* explicitly instead of auto-detect. |
| Microsoft login loops | Delete `%APPDATA%\Bot Remote\auth-cache\<bot-id>` and sign in again. |
| Server won't start on Render | Logs show which variable is missing (`DATABASE_URL`, `TOKEN_PEPPER`). |
| After a Render redeploy bots keep running | Expected: the agent reconnects automatically (2 s → 60 s backoff); the phone does too. |
